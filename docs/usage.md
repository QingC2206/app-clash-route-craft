# ClashRouteCraft

ClashRouteCraft 是面向 Clash / Mihomo 的可视化配置工作台。当前程序文件名为 `ClashRouteCraft.exe`。

首次启动会恢复缺失的通用 Example 模板。填写并拉取完整订阅后即可生成配置，住宅出口可选。已有配置不会因模板恢复而覆盖。

默认使用列表中第一个启用的订阅提供分流规则，其余订阅仅提供节点。在“订阅与入口”中上下移动即可更换主订阅；如果其缓存只有节点，请先拉取完整订阅，不会自动改用其他订阅的规则。

节点附带的 `hosts` 解析依赖也会保存：主订阅保留完整映射，其他订阅只带入节点服务器及后续域名别名所需的映射，包含节点 provider 的依赖。通配依赖按实际主机名保存，支持 IPv4、IPv6、IP 列表和连续域名别名；节点的 server、TLS/SNI 和 UDP 选项保持原值。不同来源给同一域名设置不同解析时会提示冲突，不按订阅优先级覆盖节点解析；别名循环也会报错，旧输出保留。这些信息跟随主 YAML，不改变 DNS 模式、服务器选择或 QUIC。

升级前的节点缓存若已丢失 `hosts`，需要在“订阅与入口”重新拉取该订阅，或导入其完整 Clash/Mihomo 配置，再生成一次。仅升级程序不会从节点列表猜测原映射，也不会自动改写已有项目或更新路由器。

订阅模式只保留三类业务动作：本地直连（DIRECT）、代理（统一使用“代理出口”）、拦截（REJECT，原 REJECT-DROP 保持静默丢弃）。主订阅中的广告、直连、业务分类及“漏网之鱼”等策略组均归并，不再单独设置。兜底规则保留主订阅的动作，例如原默认代理转为 `MATCH,代理出口`，原默认直连仍为 `MATCH,DIRECT`。

归并不依赖任何机场或分组名称。手选组沿 `default-selected` 或第一个候选递归解析到实际动作；自动测速、回退和负载均衡组的候选须属于同类动作。混合直连/代理/拦截而又没有明确默认动作的自动组会报错，请将来源改为有明确默认项的手选组。界面中的“查看订阅策略归并”可以预览结果。它读取订阅文件，不读取路由器里曾手动保存的选择。

匹配条件、顺序、正则、逻辑条件、IP 参数和规则来源依赖保留。PASS / PASS-RULE 及 SUB-RULE 保留内核控制流，不作为用户需要设置的第四类策略；同条件后续规则不会被去重删除。仅供节点 `dialer-proxy` 使用的旧分组作为隐藏的连接依赖保留，避免代理链断裂。

订阅模式直接使用主订阅规则，不需要再导入规则集，因此界面只显示“分流规则”和“DNS 策略”两个标签，滚动只发生在当前标签的内容区域。旧项目已有的附加规则集仍可通过“管理已有规则集”查看、停用或移除；它们是否生效仍由个人附加规则总开关和各规则集开关决定。独立规则集导入保留在自定义编排模式中。

直连组顶部的“局域网及回环地址直连”用于路由器、NAS、打印机等内网地址，避免这些连接误走代理。它是一条附加分流规则，与 URL 名单无关；主订阅已有同类规则时无需重复补充，关闭个人附加规则时也不会应用。回环地址（例如 127.0.0.1）指运行 Mihomo 的设备，MC2 中即路由器。该规则使用 `no-resolve`，不会为判断本条 IP 规则额外发起 DNS 查询；关闭它也不会删除主订阅中的同类规则。参见 [Mihomo 规则说明](https://wiki.metacubex.one/config/rules/#no-resolve)。

个人附加规则优先于主订阅规则，可在“规则与 DNS”中整体停用，原内容保留。自定义规则严格按界面三组的上下顺序输出：上一组的全部规则匹配完，再进入下一组；手工名单、URL 名单和导入规则都遵循这个顺序。旧 `first` 和补充规则按实际动作归组，不再跨组置顶。组内保留原有相对顺序；导入规则集中的不同动作会按组重新排列，同动作规则之间仍保持顺序。

例如直连组在拦截组之前时，直连 URL 名单中的域名也优先于拦截组的手工名单。冲突按输出顺序匹配，不自动把精确域名提到后缀规则前，也不删除同条件的其他动作；需要例外时，将对应的直连或代理组移到拦截组之前。自定义的 `PASS` / `PASS-RULE` 仅保留继续匹配语义，不作为业务动作参与三组竞争；主订阅规则及其控制流顺序保持不变。

所有代理规则（含附加规则中原有的具体节点、机场或住宅目标）统一使用“代理出口”。该组只选择住宅出口或机场入口：有住宅默认住宅，否则默认机场；不会自动回退到直连。住宅出口组默认第一条 `[链式]` 路径，经机场连接住宅。`[直连]` 路径则直接连接住宅代理，仍从住宅 IP 出站，与业务 DIRECT 不同。已有项目重新生成即可采用这套归并；客户端曾保存的选择可能优先于配置顺序，导入后应核对“代理出口”的当前选择。

链式住宅使用“机场入口”手选组，默认选择“聚合组”，也可以选择按实际订阅名称生成的分组。聚合组包含所有启用订阅筛选后的节点；每个订阅组只包含该订阅筛选后的节点。各组内多个候选自动测速、单个候选直接使用，不生成机场优先级分层。默认筛选香港、日本、台湾、新加坡，排除流量、到期等提示项及静态住宅项；筛选和测速参数可在订阅页面修改，已有自定义筛选保留。没有符合条件的订阅不生成空分组；若全部为空，生成会明确报错。订阅顺序仅用于确定规则来源，不作为入口的故障切换优先级。

订阅基线默认不生成或覆盖 DNS，不主动加入 GEO / ASN 规则。MC2 继续使用自身已验证可联网的默认 DNS；只导入主配置即可。主订阅自带的规则及其数据库、规则来源依赖仍需客户端支持。旧项目可勾选“使用第一个启用订阅的规则”切换；保留的旧 DNS 设置不会应用。

## 可选的 Fake-IP DNS 隐私增强

在“规则与 DNS → DNS 策略”开启“DNS 隐私增强（Fake-IP）”，保存并重新生成即可。代理 DNS 默认经住宅出口，也可选择机场入口。没有所选出口时明确报错，不自动回退到直连。开关和出口跟随项目保存；默认关闭，旧项目不会自动迁移。原有 DNS 文本保留，关闭增强后恢复原模式。

访问 Claude 等服务且希望减少 DNS 出口不一致时，可考虑开启；日常场景通常保持默认。收益是加密查询、减少代理域名的本地 DNS 暴露，代价是首次查询或连接可能稍慢、依赖所选出口，并可能遇到少数应用的 Fake-IP 兼容性问题；缓存和连接复用可减轻后续开销。这是 DNS 隐私选项，不能保证避免平台风控。代理 DNS 的连接方式见 [Mihomo DNS 说明](https://wiki.metacubex.one/config/dns/)。

增强方案使用普通域名 Fake-IP、海外 DoH 经所选代理出口、国内 DoH 用于直连连接及节点服务器域名解析。localhost 使用本地 hosts；局域网自定义域名依赖现有本地 DNS / hosts 设置。不会将订阅规则再转换为 DNS 名单，不新增域名库，不改动节点协议、业务规则或 QUIC。原订阅自带的 GEO 依赖仍保留。未命中域名规则而走到 GEOIP 判断的域名可能先经代理查询，判定直连后再次使用国内 DNS；本功能不承诺所有最终直连域名从未经过海外查询。

普通 Mihomo 客户端直接读取主 YAML 的 DNS，仍需确认客户端未覆盖它。此选项只影响内核处理的 DNS，不会自动接管浏览器独立 DoH、设备绕行、IPv6 或路由器自身 DNS。

## MC2 应用和恢复

MC2 1.2.2 导入时只保留代理、策略组和规则等字段，启动时拼入自己的 DNS 模板，所以主 YAML 中有 DNS 不代表已生效。

1. 保存当前可联网的主配置，以及 MC2 DNS 页中原来的文本。
2. 导入生成的 `HomeChain.yaml` 并选择它，先保留默认 DNS，确认主配置可启动。
3. 复制 `HomeChain.MC2DNS.yaml` 的全文（包括 `dns:`），粘贴到 MC2“DNS 设置 → 编辑 Fake-IP”。增强文件保留 Fake-IP，不会改成 Redir-Host。
4. 选择 Fake-IP，保存并重启。在 MC2“当前配置”中检查 `enhanced-mode`、`nameserver` 和出口组名，随后验收联网。

恢复默认时：关闭软件的增强开关，保存并重新生成；将 `HomeChain.MC2DNS.Default.yaml` 全文粘贴到“编辑 Fake-IP”，选择 Fake-IP，保存并重启。必要时重连设备或清理设备 DNS 缓存。**只关闭软件开关或重新导入主 YAML，均不会自动撤销 MC2 已保存的增强 DNS。**

MC2 目标每次成功生成都会带上 `HomeChain.MC2DNS.Default.yaml` 和 `HomeChain.DNS-README.txt`。恢复文件是 MC2 1.2.2 ARM64 安装包 `merlinclash/yaml_dns/fakeip.yaml` 的原装 DNS 内容，文件头注明来源及原始 SHA-256。它不依赖住宅组，也不包含订阅、节点或凭据；保留原装 `geosite:gfw` 引用，使用 MC2 原有的 GeoSite.dat，不提供或下载新数据库。它仅恢复该版本默认 DNS，不是完整配置备份；若此前自行改过默认 DNS，应恢复自己保存的文本。

即使项目生成失败或输出文件被删除，也可在“DNS配置输出(MC2专用)”中点击“复制官方默认 DNS（用于恢复）”，从程序内置资源取回原版。恢复文件不受当前项目编辑或内核校验失败影响。

Mihomo 与 GeoData 可按程序提示独立下载；本发行包不包含这些资源或 MC2 安装包。个人项目、订阅、凭据、缓存和生成结果仅保存在自己的工作区，不应上传到公开仓库。

源码构建和测试命令见仓库根目录 README.md。随包第三方说明位于 THIRD-PARTY-NOTICES.md，验证流程位于 VALIDATION.md。
